# Diagram cards

Use image occlusion when the learning requirement includes identifying a structure
in an image or locating a labelled feature. A relevant image may instead belong
on a textual card's back. Clinical images and decorative figures do not
necessarily need masks.

For a lecture, inspect the figure inventory once and choose figures by uncovered
learning requirements. Prefer a representative view over repeated versions; do
not select only the cleanest figure if another tests the needed structure.
Record meaningful skipped figures with a short reason. Scope this to the user's
requested material; a one-diagram task needs no lecture-wide figure survey.

Inspect the actual image before placing masks. OCR proposes labels/rectangles;
it is not proof that every label was detected or correctly read. Use page renders
for garbled extraction and adjust masks manually where needed.

Each tested group should hide the intended answer completely without obscuring
the anatomy needed to identify it. Repeated labels for the same target may need
the same group so another copy does not reveal the answer. Check titles, legends,
leader lines and neighbouring text for leakage. Preserve useful orientation and
visual landmarks.

Inspect each distinct generated question and its answer view, including grouping
and mask boundaries. A single outline preview does not prove that every hidden
state works. If a target cannot be identified reliably from the image, leave that
card unresolved or choose another view.

AnkiPlus's occlusion builder returns fields and media; save the intended note
explicitly. Follow the installed tool schema and actual note-type requirements.
Store media and write notes only within the user's authorization. Verify that
media resolves and generated card groups match the inspected questions. Report
note counts separately from generated card counts.
